可以。下面给你一份**直接从“根治生成端”开始**的完整方案，默认目标是：

> **先把 pseudo-view 的图像质量和相机几何对齐修正好，再重生 pseudo，再重新跑 raw / conf / full 三组。**

我不再从“止血版灰边 mask”开始，而是直接从**生成端根治**开始。

---

# 总体目标

先解决这两个根因：

1. **DynamiCrafter 预处理导致灰边 / padding**
2. **pseudo 图像经历 resize/crop 后，写回训练时的 intrinsics 没同步更新，造成 FOV mismatch**

只有这两个解决了，后面的：

* confidence
* consistency
* frame filtering
* hybrid training

才是在“干净 pseudo”上工作。

---

# Phase 1：重构 DynamiCrafter 输入预处理

## 1.1 目标

保证输入到 DynamiCrafter 的图像：

* **没有左右灰边**
* **没有靠 padding 补出来的内容**
* **输出分辨率和后续 intrinsics 变换可追踪**

---

## 1.2 不再使用当前的 `Resize(min) + CenterCrop`

你现在这条链会导致：

* 原图 `512x384`
* 目标 `512x320`
* 宽度不够时左右 padding
* padding 在反归一化后变灰边

### 要改成

**resize-to-fill + center crop**

也就是：

* 先按 `max(target_w / w, target_h / h)` 缩放
* 保证缩放后图像的宽和高都 **不小于目标尺寸**
* 再做 center crop
* **绝不允许 padding**

---

## 1.3 推荐保留目标尺寸为 `320x512`，但改预处理逻辑

这是最稳妥的第一版。

### 原因

* 不需要动 checkpoint 假设
* 不需要马上验证 `384x512` 是否完全兼容模型
* 先根治灰边，再看是否需要进一步提升分辨率一致性

---

## 1.4 需要改的文件

### `part3/src/part3_stack/dynamicrafter_adapter.py`

把输入预处理封装成你自己的函数，不要直接信任 demo 默认行为。

### `part3/DynamiCrafter/scripts/gradio/i2v_test_application.py`

如果当前 adapter 直接走这套逻辑，要么：

* 改原函数
* 要么在 adapter 里旁路掉这套预处理，自己先处理完再送进去

---

## 1.5 建议实现

新增一个明确的预处理函数，输出：

* 处理后的图像
* scale
* crop offset
* 处理前后尺寸信息

伪代码：

```python id="16om1s"
def preprocess_resize_to_fill(img, target_h=320, target_w=512):
    h, w = img.shape[:2]
    scale = max(target_w / w, target_h / h)

    new_w = int(round(w * scale))
    new_h = int(round(h * scale))
    img_rs = resize(img, (new_w, new_h))

    x0 = (new_w - target_w) // 2
    y0 = (new_h - target_h) // 2
    img_crop = img_rs[y0:y0 + target_h, x0:x0 + target_w]

    meta = {
        "orig_h": h,
        "orig_w": w,
        "new_h": new_h,
        "new_w": new_w,
        "target_h": target_h,
        "target_w": target_w,
        "scale": scale,
        "crop_x0": x0,
        "crop_y0": y0,
    }
    return img_crop, meta
```

---

## 1.6 这一阶段的验收标准

你要检查：

* pseudo 图像左右边缘不再有固定灰边
* 边缘“灰色/低饱和像素比例”明显下降
* 左右边缘平均灰边宽度接近 0

---

# Phase 2：同步更新 pseudo 相机 intrinsics

这是和生成端同等重要的一步。

## 2.1 目标

任何 pseudo 图像只要经历了：

* resize
* crop

就必须同步更新它对应的内参 `K`。

否则你虽然去掉了灰边，**几何仍然是错的**。

---

## 2.2 你要做的变换

如果原内参为：

[
K=
\begin{bmatrix}
f_x & 0 & c_x \
0 & f_y & c_y \
0 & 0 & 1
\end{bmatrix}
]

经过 scale `s` 和 crop 偏移 `(x0, y0)` 后：

[
f_x' = s f_x,\quad f_y' = s f_y
]
[
c_x' = s c_x - x0,\quad c_y' = s c_y - y0
]

---

## 2.3 需要改的地方

### `coarse_geometry.py`

新增或修改一个函数：

* 根据 preprocessing meta 更新 pseudo intrinsics

建议新增：

```python id="8yx3tr"
def transform_intrinsics(K, scale, crop_x0, crop_y0):
    K_new = K.copy()
    K_new[0, 0] *= scale
    K_new[1, 1] *= scale
    K_new[0, 2] = K[0, 2] * scale - crop_x0
    K_new[1, 2] = K[1, 2] * scale - crop_y0
    return K_new
```

---

## 2.4 这一步必须同步影响的模块

你不能只改 hybrid 写回。下面几处都要统一：

1. **coarse render**
2. **pose refinement**
3. **reprojection error**
4. **confidence 的 `C_reproj`**
5. **frame filtering**
6. **hybrid 写回 pseudo camera**

也就是说：

> 以后 pseudo 图像一律用 `K_pseudo`，不是原始 real-view 的 `K`。

---

## 2.5 验收标准

你要看：

* coarse render 与 pseudo-view 的视角对齐明显改善
* pose refinement 成功率上升
* reprojection error 降低
* frame score 更稳定

---

# Phase 3：重建 pseudo 相机链路

## 3.1 目标

让每个 pseudo-view 有一套自洽的数据：

* `image`
* `pose`
* `K_pseudo`
* `coarse render`
* `reprojection score`

而不是以前那种：

* 图像经过裁剪/缩放
* 但相机还是旧的

---

## 3.2 推荐改法

在 `generate_pseudo_views()` 的输出 manifest 中，为每张 pseudo 额外写：

* `preprocess.scale`
* `preprocess.crop_x0`
* `preprocess.crop_y0`
* `intrinsics_pseudo`
* `orig_resolution`
* `pseudo_resolution`

示例：

```json id="gi5ld8"
{
  "image_name": "pseudo_pair_0001_00.png",
  "pose": {...},
  "intrinsics_pseudo": [[...], [...], [...]],
  "preprocess": {
    "orig_h": 384,
    "orig_w": 512,
    "new_h": 384,
    "new_w": 512,
    "target_h": 320,
    "target_w": 512,
    "scale": 1.0,
    "crop_x0": 0,
    "crop_y0": 32
  }
}
```

## 3.3 需要改的文件

* `pipeline.py`
* `dynamicrafter_adapter.py`
* `coarse_geometry.py`

# Phase 4：重新生成 shared pseudo views

## 4.1 必须重生

这一步不能省。

原因很简单：

* 旧 pseudo 已经带灰边
* 旧 pseudo 的 FOV 已经错了
* 在旧 pseudo 上重跑 conf/full 没意义

---

## 4.2 重生顺序

建议这样跑：

1. 修 preprocess
2. 修 `K_pseudo`
3. 重新生成 shared pseudo
4. 先做质检，不急着训练

---

## 4.3 质检项目

对新 pseudo 做这几项检查：

### 图像侧

* 左右边缘灰边宽度
* 边缘灰色/低饱和像素比例
* 中心区域模糊度

### 几何侧

* coarse L1
* reprojection error
* pose refinement 成功率
* PnP inlier 数

### 建议阈值

先设硬门槛：

* 灰边宽度接近 0
* reprojection error 明显低于旧版
* refinement 成功率比旧版高

---

# Phase 5：重新跑 raw / conf / full 三组

## 5.1 这次三组的区别应该只来自训练策略

重新生成 pseudo 后，再跑：

* `gen_raw`
* `gen_conf`
* `gen_full`

这样它们共享同一套干净 pseudo。

---

## 5.2 先用保守训练设置

不要一上来让 pseudo 主导训练。

建议第一轮先保守：

```json id="qj6a20"
"pseudo_ratio_mid": 0.15,
"pseudo_ratio_final": 0.25,
"pseudo_weight_mid": 0.1,
"pseudo_weight_final": 0.2,
"pseudo_warmup_iters": 3000,
"pseudo_full_iters": 10000
```

这样更容易看出：

* 新 pseudo 是否至少不再拖垮真实 test

---

## 5.3 这轮先不追求 30000 iter

先固定看几个 checkpoint：

* 1000
* 3000
* 7000
* 10000
* 30000

最终只看：

* `real_only full-image PSNR/SSIM/LPIPS`

选择真实 test 最好的 checkpoint，而不是默认 30000。

---

# Phase 6：在干净 pseudo 上再启用 conf + consis

只有到这一步，confidence 和 consistency 才值得认真比较。

---

## 6.1 confidence 的建议结构

保持下面这个设计：

[
M = C_{vis} \cdot C_{patch} \cdot (\lambda + (1-\lambda)S)
]

其中：

* `S = 0.4 C_reproj + 0.3 C_feat + 0.3 C_temp`
* `\lambda = 0.3`

也就是：

```python id="eev4ph"
soft_conf = 0.4 * c_reproj + 0.3 * c_feat + 0.3 * c_temp
final_mask = c_vis * c_patch * (0.3 + 0.7 * soft_conf)
```

### 同时

pseudo loss 继续使用 **normalized masked loss**。

---

## 6.2 consistency 的建议结构

* `clip_score` **只影响采样概率**
* 不再同时影响 loss scalar
* patch pruning 继续留在空间 mask 里

这样避免 consistency 双重降权。

---
