## 1. 总体框架怎么定

### 你要采用的不是“完整复现 ReconX”

而是一个 **ReconX-style 工程实现**：

1. **Part 2 输出**作为底座
   你已经有 sparse views、估计 poses、以及一个初始重建结果。

2. **DynamiCrafter** 作为视频扩散生成器
   DynamiCrafter 的强项是：把单张图作为 guidance 注入视频扩散，生成连贯视频；它依赖文本到视频的 motion prior，并通过图像上下文表示和把整张图拼到噪声里来保留细节。([ECCV 2026][2])

3. **用几何条件约束 DynamiCrafter，而不是裸跑**
   因为 DynamiCrafter 本身不是为 3D sparse reconstruction 设计的，它擅长“视频感”和“运动逻辑”，不天然保证严格几何一致。

4. **生成出来的 pseudo-views 只作为辅助监督，不作为真值**
   这一点非常关键。ReconX 也是“生成 → 再做 confidence-aware 3DGS”，不是把生成图无脑当 GT。([Hugging Face][1])

## 2. 你的整体实现骨架

我建议你把整个方法拆成 6 个模块。

### 模块 A：Part 2 底座准备

输入：

* 稀疏真实图像 `I_real`
* Part 2 估计的 pose / intrinsics
* Part 2 初始重建（point cloud 或 3DGS）
* baseline 渲染结果

输出：

* 一个可在任意插值位姿处渲染 coarse RGB / depth / normal / alpha 的底座

这里的作用是：
**给生成模块提供几何 guidance，也给后面的 confidence 和 consistency 提供参考坐标系。**

---

### 模块 B：伪视角轨迹生成

按 ReconX 思路，你不是孤立生成一张图，而是在 sparse views 之间补一段“局部视频”。

做法：

* 从相邻 sparse frames 里取 anchor pair：`(I_i, I_{i+1})`
* 对两帧 pose 做插值，得到中间轨迹 `P_{i,1}, P_{i,2}, ..., P_{i,k}`
* 每个 `P_{i,t}` 都有一个理论相机位姿

关键点：

* 轨迹要短、局部、连续
* 不要跨太大 baseline
* 宁可多生成短 clip，也不要强行跨大视差

这是因为 DynamiCrafter 适合生成**局部连续视频**，而不是任意大跨度的严格 novel view。([ECCV 2026][2])

---

### 模块 C：DynamiCrafter 生成 pseudo-view clip

这一层是你“Generative Enhancement”的核心。

#### 输入建议

给每个 anchor pair：

* 起始真实图 `I_a`
* 终止真实图 `I_b`
* 对应插值位姿列表 `{P_t}`
* 当前底座在 `{P_t}` 上渲染的：

  * coarse RGB
  * depth
  * normal
  * alpha / visibility

#### 输出

* 连续 pseudo-view clip：`{I^pseudo_t}`
* 每帧对应初始 pose：`{P_t}`

#### 工程上怎么做

你可以做两种模式：

**模式 1：最小可行版**

* 直接用 `I_a` 作为主条件做 DynamiCrafter 生成短视频
* 用 `I_b` 作为 clip 筛选参考，而不是直接条件输入

**模式 2：更推荐**

* 用 `(I_a, I_b)` 定义一段 interpolation-style clip
* 再结合 coarse render 做后验筛选

关键点不是“生成得多漂亮”，而是：

* 生成帧和理论轨迹对不对得上
* 相邻生成帧之间是否平滑
* 和当前重建几何是否兼容

---

### 模块 D：pseudo-view pose 绑定与微调

不要直接假设“生成第 3 帧 = 插值轨迹第 3 个 pose”就完全成立。

建议流程：

1. **初始化**：直接赋给对应插值 pose
2. **小范围 refinement**：

   * photometric alignment
   * 或 feature matching + PnP / SE3 refinement
3. **帧筛选**：

   * reprojection error 太大就丢
   * 与相邻帧 flow 不一致就降权
   * 与 coarse render 差异过大就降权

这一步决定后面的 confidence map 基准是否可靠。

## 3. Confidence Fusion 怎么设计

这一部分最适合吸收 **OVIE**。

OVIE 的核心启发非常明确：
它用单目深度 lift 出 3D 点云，再在目标视角重投影，得到 pseudo-target 和 **binary visibility mask**；mask 中 1 表示 valid reprojected pixels，0 表示 disocclusion、遮挡边界、背面、出框内容。更重要的是，它不只对 RGB loss 加 mask，还把 perceptual loss 也限制在 valid regions，目的是 suppress invalid gradients。

所以你的 Confidence Fusion 最合理的设计是：

### 3.1 设计成“软置信度图”，不是单一二值 mask

定义每张 pseudo-view 的像素级权重：

[
C(x)=C_{\text{vis}}(x)\cdot C_{\text{reproj}}(x)\cdot C_{\text{feat}}(x)\cdot C_{\text{temp}}(x)
]

其中：

#### 1) `C_vis`

来自 OVIE 的 **有效性掩码思想**：

* 当前底座几何在该像素可见
* 不在遮挡边界
* 不在 backface / out-of-frame / hole 区域

这是一层 hard/soft validity。
**它回答的是：这个像素有没有资格参与监督。** 

#### 2) `C_reproj`

重投影一致性：

* 把 pseudo-view 像素回投到邻近真实视图
* 和真实视图做颜色或特征对比
* 误差小则高权重，误差大则低权重

**它回答的是：这个像素和真实观测对不对得上。**

#### 3) `C_feat`

来自 GLD 的 **cross-view correspondence** 思想。
GLD 的核心观点是：multi-view diffusion 最需要的是 latent 中已经带有跨视角几何对应关系，而不是只在 VAE latent 里做外部几何约束；它强调 geometry foundation model 的特征里有更强的 cross-view correspondences。

所以你可以：

* 用 VGGT / DA3 / DUSt3R / DINO 中层特征
* 比较 pseudo-view 与邻近真实视图的 feature agreement
* correspondence 强 → `C_feat` 高
* correspondence 弱 → `C_feat` 低

**它回答的是：这块区域在“几何特征层面”是不是也一致。**

#### 4) `C_temp`

时序一致性：

* 由连续 pseudo-frames 的 optical flow forward/backward consistency 给出
* flow cycle error 小 → 高权重
* flicker / deformation 大 → 低权重

**它回答的是：这块区域在局部视频里稳不稳定。**

---

### 3.2 关键点：mask 不只乘 RGB loss，也要乘 perceptual loss

这点直接学 OVIE。

你应该写成：

[
L_{\text{pseudo}} =
\lambda_{rgb}, C \odot |I^{pred}-I^{pseudo}|
+
\lambda_{perc}, C \odot L_{perc}(I^{pred},I^{pseudo})
]

而不是只给 RGB 上 mask。

因为 OVIE 明确表明：
如果 perceptual loss 不 mask，invalid region 仍会产生错误梯度。

---

### 3.3 关键点：confidence 不是离线一次算完

建议做成 **online update**：

* 第 0 轮：用 Part 2 底座算一版 `C`
* 训练若干 steps 后：重新渲染、重新算 reprojection / feature consistency
* 如果某些 pseudo-view 越来越和当前几何不一致，就继续降权或移除

这会比“一开始固定一个 mask 用到底”更稳。

## 4. Consistency-Aware Optimization 怎么设计

这一部分最适合吸收 **GLD**。

GLD 不是单纯说“图像更好看”，而是系统性强调：

* novel view synthesis 需要 **geometrically consistent generation across viewpoints**
* 不能只在 view-independent VAE latent 里生成
* 要看 **cross-view correspondences**
* 要用 **ATE / RPE / reprojection error / MEt3R** 这些 3D consistency 指标去衡量结果。

所以你的 Consistency-Aware Optimization 应该这样设计：

### 4.1 不把 pseudo-views 当独立图片，而把它们当一个“局部耦合 clip”

这是最重要的设计思想。

你不是：

* 随机抽一张 pseudo-view，单独监督

而是：

* 以一个 anchor pair 生成一个 clip
* clip 内帧之间共享局部几何关系
* 一致性评分也按 clip 来做

这样更接近 ReconX 的“temporal generation”视角，也更接近 GLD 的“joint multi-view coupling”。([Hugging Face][1]) 

---

### 4.2 一致性分数用“几何量”，不只用像素差

你可以定义：

[
S_{\text{cons}} = w_1 S_{\text{flow}} + w_2 S_{\text{reproj}} + w_3 S_{\text{feat}} + w_4 S_{\text{pose}}
]

其中：

#### `S_flow`

相邻 pseudo-frames 的光流前后向一致性

#### `S_reproj`

利用当前重建几何，把一帧 reproject 到另一帧，测重投影误差

#### `S_feat`

用几何 foundation model 中层特征测跨视角一致性
这就是从 GLD 借来的核心灵感：
**不要只在 RGB 上看一致，要在 geometry-aware feature 上看。** 

#### `S_pose`

pose-refined 后，连续帧轨迹是否平滑、是否存在突跳

---

### 4.3 关键点：一致性惩罚应该转化成“区域降权”，而不是简单删整帧

项目书里要求的是：

> 用 optical flow 或 reprojection error 自动 down-weight unreliable regions during training。

所以更推荐：

* 像素级 / patch 级降权
* 不是整张图粗暴剔除

实践上可以这么做：

#### 方案 A：pixel reweighting

* 光流不一致的区域：权重衰减到 0.1～0.3
* 重投影误差高的区域：权重衰减到 0～0.2
* 几何特征不匹配区域：进一步衰减

#### 方案 B：patch pruning

* 按 16×16 或 32×32 patch 计算 consistency
* 低分 patch 不参与 pseudo loss

这个比逐像素更稳定，也更省算力。

---

### 4.4 关键点：训练调度要分阶段

Consistency-aware optimization 不能一开始就把大量 pseudo-view 强行压进训练。

建议分三阶段：

#### Stage 1：real-only warmup

只用真实 sparse views

* 让当前几何先稳定

#### Stage 2：real + pseudo low-weight

* pseudo-view 少量引入
* 全局权重低
* 强依赖 confidence mask

#### Stage 3：consistency-aware full hybrid

* 增加 pseudo-view 占比
* 但持续根据 consistency 分数重加权

这个调度能显著减少 geometry drift。

## 5. OVIE 和 GLD 各自到底提供了什么“可落地模块”

可以这么记：

### OVIE 提供的是：**“哪些像素值得学”**

你要借它三件事：

1. **几何生成 pseudo-target 的 valid mask 思想**
2. **invalid region 不仅不参与 RGB loss，也不参与 perceptual loss**
3. **基于几何重投影的有效性筛选优先于视觉好不好看** 

这会直接变成你的：

* `C_vis`
* masked LPIPS / masked feature loss
* 可见性优先的 confidence fusion

---

### GLD 提供的是：**“哪些伪视角在跨视角上自洽”**

你要借它四件事：

1. **几何 foundation model 特征比普通 VAE latent 更适合做跨视角一致性判断**
2. **source/target 是联合耦合的，不该独立看**
3. **中层特征常常比 RGB 更适合做 correspondence 检查**
4. **评价要引入 pose/reprojection/3D consistency，而不只看 PSNR** 

这会直接变成你的：

* `C_feat`
* clip-level coupling
* reprojection / feature consistency reweighting
* 更有说服力的 ablation 和评估

## 6. 一版你可以直接写进方法里的设计

### 6.1 方法总述

> We follow a ReconX-style generative enhancement pipeline. Sparse-view reconstruction from Part 2 provides geometry priors and camera trajectories. A DynamiCrafter-based video diffusion model synthesizes pseudo-views along interpolated camera paths. The generated views are not treated as ground-truth, but are incorporated into reconstruction via confidence-aware hybrid optimization. Confidence maps are constructed by combining geometry-derived visibility, reprojection agreement, feature-level correspondence, and temporal consistency. Unreliable regions are automatically down-weighted during training.

---

### 6.2 Confidence Fusion 公式

[
C = C_{\text{vis}} \cdot C_{\text{reproj}} \cdot C_{\text{feat}} \cdot C_{\text{temp}}
]

* `C_vis`：visibility / occlusion / boundary validity
* `C_reproj`：reprojection agreement with nearby real views
* `C_feat`：geometry-aware feature correspondence
* `C_temp`：optical-flow temporal stability

然后：

[
L = L_{\text{real}} + \alpha \sum_{j \in pseudo} C_j \odot
(\lambda_1 L_1 + \lambda_2 L_{perc} + \lambda_3 L_{ssim})
]

关键点：

* `L_real` 不降权
* `L_pseudo` 必须按像素或 patch 加权
* perceptual loss 也一起加权

---

### 6.3 Consistency-Aware Optimization 规则

对每个 pseudo clip：

1. 算相邻帧 forward/backward flow consistency
2. 用当前几何算 cross-view reprojection error
3. 用中层 feature 算跨视角一致性
4. 得到 clip score 和 pixel score
5. 低分区域降权，极低分帧移出训练池

---

## 7. 实现时最容易踩的坑

### 坑 1：把 DynamiCrafter 输出直接当 GT

这是最危险的。
正确做法是：**辅助监督 + 置信度加权**。

### 坑 2：只做整帧分数，不做区域分数

很多伪视图只有一小部分坏。
整帧丢掉太浪费，整帧保留又太危险。
所以最好做像素级或 patch 级重加权。

### 坑 3：只看 RGB consistency

GLD 的启发恰恰在于：
**跨视角一致性更应该看 geometry-aware feature correspondence。** 

### 坑 4：一开始就大量注入 pseudo-view

这很容易把 Part 2 的几何带偏。
先 real-only warmup，再小权重引入。

## 8. 你这个方案的“最关键三点”

我帮你压成最核心的三句话：

### 第一

**ReconX 提供总骨架**
先用底座几何约束视频扩散生成伪视角，再用置信度感知的 3DGS 融合它们。([Hugging Face][1])

### 第二

**OVIE 提供 confidence 的底层设计原则**
无效区域不要监督，而且不仅 RGB loss 要 mask，perceptual loss 也要 mask。

### 第三

**GLD 提供 consistency 的上层设计原则**
不要把伪视角孤立看，要用跨视角几何特征、重投影和时序一致性来决定哪些区域可信。
